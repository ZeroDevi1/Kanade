# RVC 窄带数据补全与对照训练

## 范围与限制

训练页的「高频补全」默认为关闭，智能和专业模式均可选择：

- **关闭**：原始音频训练基线，不下载 AP-BWE。
- **自动**：先检测整个已选数据集的频谱截止，再逐条核对，只处理需要补全的音频。
- **手动**：给出 2000–14999 Hz 的可信截止频率。不能把文件头采样率直接当作有效带宽。

AP-BWE 生成的是估计的高频，不是真实原声恢复；它不能补齐真实歌唱、换声区或 F0 覆盖。原始低频在频域拼接中保留，截止前 300 Hz 为交叉过渡；若补全导致峰值超限，整段统一衰减以避免削波（此时低频幅度也会缩小）。先试听，再决定是否训练。

## 操作

1. 选择单层数据集目录。存在同名 `.list` 时只使用其中列出的音频；标注缺失文件会明确报错。未列出的音频、子目录中的音频不会混入训练。
2. 选择自动或手动补全，点击「试听」按钮。默认生成最多 3 组（API 允许 1–5 组），不会启动 RVC 训练。
3. 在结果列表切换原始/补全音频；检查齿音、气声、长元音和喊声。按相同响度比较，不要仅因为更亮或频谱更多就选补全版。JSON 报告记录截止频率、所选模型及哪些片段试听。
4. 使用新模型名开始训练。BWE 输出在实验目录 `_dataset_bwe`，不覆盖原数据；后续切片、音高与内容特征都从这一份输入生成。
5. 自动采样率在确实存在补全片段时选 48k；专业模式可固定采样率用于对照。没有补全时按实际选中音频的采样率选择，不能混用未选音频影响参数。

训练首次需要下载所选 AP-BWE safetensors 和配置；取消会终止子进程，不会继续进入训练。预览产物使用应用的临时结果区，需要时点保存。自动检测对不可读文件不做补全，报告会说明；请先转成 WAV 再评估。

## 缓存与续训

- 原始 WAV 以内容 SHA256 识别；补全缓存另外包含模型权重、配置 SHA256 和算法版本。
- 训练元数据 `kanade-train.json` 记录数据指纹、采样率、F0、切片、归一化及补全参数。
- 改数据、选取范围、补全模式/截止、模型权重或预处理参数，必须使用新的实验名；不会悄悄沿用旧切片、特征或 G/D 检查点。
- 重新预处理会清除相应的可再生切片与特征缓存；重新提取也会清除旧 F0/embedding，避免 vendor 脚本按文件名跳过。
- 只有所有切片的 embedding、F0 和 voiced-F0 都准备成功，才允许跳过准备阶段续训。中断后重新运行完整准备。
- **旧实验没有数据指纹时，不允许直接续训/跳过准备。** 请用新模型名重建实验，旧权重保留不变。这是有意的安全限制，不能验证的旧缓存不自动信任。

## 最小 A/B/C 实验

- A：补全关闭，新实验，从匹配采样率的预训练权重训练。
- B：训练前 AP-BWE 补全，新实验，从与 A 相同的预训练权重训练。
- C：A 模型的转换结果再独立经过 BWE，用于比较后处理收益。当前训练 UI 不自动实施 C，不要把输入原唱的高频直接混入输出作为“恢复”。

A/B 固定采样率、batch、有效更新步数、F0 算法、推理检索比例和测试曲目。保存多个阶段 checkpoint，不能只比较最终一轮或最低训练 loss。测试包含中低音、高音、齿音和长音，且不进入训练集。记录音色相似度、清晰度、齿音伪影与高音稳定性。没有真实宽带参考时，高频能量增加不是恢复准确率。

## 开发验证

CPU 工作流测试（不下载模型，不依赖 torch）需要 Python、numpy、soundfile、soxr：

    PYTHONPATH=engines/timbre/src:engines/sdk/src python -m unittest discover -s engines/timbre/tests -v
    CGO_ENABLED=0 go test ./...
    go tool mygo vet .

模型推理与真实 CUDA/MPS 训练需另做小样验收。mock 流程测试不能证明 AP-BWE 音质改善。
