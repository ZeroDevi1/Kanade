## 2. 音乐分析的乐谱

- 五线谱的旋律只量化到八分音符（八分音符按半小节 / 单拍加符杠），没有三连音与十六分音符；人声识别误差下更细的网格
  会产生大量碎音符，需要先做节奏量化的平滑（例如按乐句对齐）再细化。
- 谱号与升降号依赖系统字体（休止符、符尾已改为路径绘制）；若 Windows 上谱号显示为方框，改为路径绘制或随应用打包音乐字体。

## 3. Synthesizer V 工程的原唱表情参数（听感不自然，待改进）

现状（2026-10-24，提交 2f7daf8）：导出 SV 工程时可把原唱的音高、响度、气声、张力、发声写成参数曲线，并按歌姬套用
预设与演唱模式（internal/score/svexpr.go、svpreset.go、svrecommend.go）。《我不想念》用 Weina（SV Studio Flat）
渲染两次，听感都不自然，**不如不调**：

- 第一版（响度以 90 百分位为 0 dB、演唱模式 Firm=74）：像憋着唱。渲染与原唱分离人声逐帧对比：音高 97% 的帧误差
  < 50 音分（音高跟踪本身没问题）；响度中位数低 16 dB、起伏从 9 dB 放大到 16 dB；5–8 kHz 噪声高 9 dB。
- 第二版（响度以中位数为 0、起伏减半、−6–+3 dB；气声 0.3、张力 0.25；Lucid=50, Firm=27）：用户反馈与第一版没有
  明显区别（未做客观对比）。

判断：问题不在某个系数，而在做法本身——

1. 音高是「覆盖式」的：音符设为手动音高（instantMode=false）、关掉 SV 的颤音与滑音，再用 pitchDelta 把原唱 F0 整条
   贴上去。这丢掉了 SV 自身按音素与音高联合建模的起音、过渡与颤音；原唱 F0 来自分离人声 + yin，含分离残留与跟踪噪声，
   与 SV 的音素时长也未必对齐，逐帧照搬反而不像人唱。
2. 声学特征 → SV 参数的映射没有标定：频谱倾斜、高频噪声、周期性与 SV 的 tension / breathiness / voicing 不是同一个量，
   z 分数加 tanh 是经验映射；同一参数值在不同声库上的效果差异很大（论坛反馈：新版 AI 声库调张力主要变成音量变化）。
3. 演唱模式按情绪关键词推荐，模式名相同、效果也因声库而异，强度没有依据。

计划（按顺序；每步都用下面的「评估」验收，达不到就不进入下一步）：

1. 止损：默认关闭全部表情曲线（强度 0），只保留歌姬、移调与音色预设，对话框把表情强度标为「实验性」；
   演唱模式不再自动填强度，只列出该声库有哪些模式。
2. 评估工具：在导出对话框或任务里加入「渲染对比」——用户把 SV 渲染的人声拖回来，按 score.expression 的特征与原唱对比
   （F0 误差、响度分布与相关、频谱倾斜、高频噪声），按乐句给出差异；同时固定 2–3 个代表乐句做 A/B 听感
   （无参数 / 仅音高 / 全部）。没有这一步，后面的改动都只能凭感觉。
3. 音高改为「引导式」：保留 SV 的 AI 音高，只在 SV 与原唱差异大的地方（转音、明显的滑音、原唱特有的音高走向）
   写少量 pitchDelta 控制点，并按音符边界平滑过渡。需要 SV 的基准音高：先导出一份无参数的工程让用户渲染
   （或用 renderConfig 的 exportPitch 导出音高），用第 2 步的工具从渲染里取 F0 作为基准，只补差值。
   SV2 另有 2.0 版本格式的 pitchControls（LibreSVIP 对 2.x 用它代替 pitchDelta），可评估是否更自然。
4. 按声库标定参数：为所选歌姬生成「参数扫描」工程（同一乐句，tension / breathiness / loudness / voicing 各取若干档），
   用户在 SV 中渲染一次，用第 2 步的工具测出每档参数对应的声学特征，拟合该声库的「参数 → 特征」曲线并保存进歌姬预设；
   导出时用它把原唱特征反解成参数。未标定的声库不写这些曲线。演唱模式同样可以加进扫描，测出各模式的声学效果后再推荐。
5. 每一步完成后重新渲染《我不想念》至少一个乐句做 A/B；验收标准：带参数的版本在盲听中不劣于无参数版本，
   且客观指标比无参数版本更接近原唱。
