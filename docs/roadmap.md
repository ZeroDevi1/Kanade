# 后续更新计划

记录已确定要做、但尚未实现的改动。完成后从这里删除，细节写进对应的提交与文档。

## 1. 一键翻唱达到手工后期的效果（优先）

背景：2026-10-20 的 Windows 实测中，《如诗一般的形容妳》炫狗翻唱的成品是在命令行里用引擎加后期脚本做出来的，
「音色转换 → 翻唱」一键流程做不到同样的效果。差别与评估数据见 [stems-evaluation.md](stems-evaluation.md)
和 [windows-test-plan.md](windows-test-plan.md)；当时的后期脚本参数记在下面各条中。

### 1.1 分轨可选模型，或默认链换成评估最优

- 现状：`stems.chain` 已支持 `models` 参数按步骤覆盖模型（按 stem 角色匹配输出），但分轨页和翻唱流水线都没有入口。
- 评估最优组合：伴奏 `model_bs_roformer_ep_317_sdr_12.9755.ckpt`、干声 `BS-Roformer-SW.ckpt`、
  去和声 `mel_band_roformer_karaoke_gabox_v2.ckpt`，去混响与降噪保持默认。
  同一首歌上，伴奏里残留的原唱（伴奏与人声的相关系数）从 0.046 降到 0.012。
- 方案二选一（需要先主观试听确认）：
  - 分轨页每一步给一个模型下拉框，默认值仍与 VoiceLab 一致，提供「评估推荐」一键切换；
  - 或直接把默认链换成评估最优，`chain.STEPS` 的注释与 VoiceLab 一致的说法同步修改。
- 注意：新模型首次使用需下载（SW 约 650 MB、1297 约 640 MB、Gabox V2 约 900 MB），下载缺失模型的按钮与体积提示要跟着改。

### 1.2 和声也做音色转换

- 现状：「混入原曲和声」混的是原唱本人的和声（`_vocals_other`），成品里能听出原唱的声音。
- 改为：和声与主唱用同一模型、同一组参数各转换一次，再混入；保留「混入原曲和声」作为可选项（有的歌和声不是主唱本人）。
- 实测：转换后的和声与目标音色相似度 0.732（主唱 0.791）。

### 1.3 按原唱响度对齐，不做峰值归一化

- 现状：翻唱时转换结果勾选「输出峰值归一化」后被拉到满幅，再以 0 dB 与伴奏相加，人声比例与原曲不一致。
- 改为：转换后的主唱 / 和声在演唱段的 RMS 分别对齐到原曲对应分轨（净化后的干声 / 和声）的 RMS，
  保持原混音的人声与伴奏比例；演唱段可用能量门限自动检测，不依赖歌词时间轴。
- 实测参考：主唱对齐到 −16.0 dBFS、和声 −29.2 dBFS 时听感接近原曲。

### 1.4 混音时加混响

- 现状：净化链去掉了原唱混响，转换后的干声直接与伴奏相加，声音发干、贴脸。
- 改为：`timbre.mix` 对人声轨支持混响发送：人工混响（指数衰减噪声脉冲响应，左右声道独立，6 kHz 低通），
  默认 RT60 1.6 s、预延迟 25 ms、湿声比干声低 12 dB；界面给开关和湿声量滑块。
- 母带：成品整体增益到峰值 −1 dBFS，导出 24 bit（现为 16 bit），可选同时导出 MP3。

## 2. 实测中发现、尚未处理的问题

- 应用没有单实例保护：重复启动会出现两个实例，各自启动 worker 争用 GPU。
- 训练表单的数值框（总轮数、batch、每 N 轮保存等）只设置了无障碍名称，界面上没有可见标签。
- CosyVoice 长文本取消在句与句之间生效，最长要等当前一句合成完。
- CosyVoice SFT：训练中途失败（例如显卡驱动重置）后，界面没有「用已保存的检查点平均并组装」的入口；
  「训练 LLM + Flow」与「无 .list 时 Whisper 转写」尚未在 Windows 上测试。
- 8 GB 显卡上分轨与训练同时运行会超出显存、回退到共享内存，速度降到几分之一：
  Conductor 只限制了自身同一时间一个 GPU 任务，空闲 worker 仍常驻显存，可考虑空闲一段时间后释放。
