# 灵感页调研：哼唱动机 → 乐句 → 和声配置 → 动机发展

状态：M1（哼唱转乐句，含自由哼唱的自适应速度，`internal/score/phrase.go`、`tempo.go`）与 M2（规则和声配置，`internal/score/reharm.go`）已实现，界面见 `inspire.go`；M3（动机发展）未开始。日期：2026-10-25。

**应用不调用 LLM**：灵感页的全部功能都是本地的确定性算法，离线可用。开发时遇到算法设计问题，由开发者向 Claude Fable 5.1（effort high）咨询，咨询结论整理进本文档或代码注释。

## 1. 目标与流程

新增导航项「灵感」。用户哼一段动机（2–8 小节），Kanade 依次做以下几步，每一步都可以手动修改：

1. **录动机**：节拍器预备拍，循环录音，录音设备沿用 K 歌的设置（`Settings.KaraokeMic`）。
2. **整理成乐句**：把音高曲线切成音符并量化到节拍网格。一个音节内连续变化的几个音（转音、滑音）归为一组连音；歌词用拟声词填充（啦 / 哒 / 嗯…），每个音节一个字，连音只占一个字。
3. **和声配置**：按风格给出几套候选和声（流行、爵士 ii–V、重配和声、调式），每套附规则生成的理论说明（为什么选这个和弦），并给出旋律与和弦的协和度评分。
4. **动机发展**：用经典手法把动机发展成 4 / 8 / 16 小节的乐段（重复、模进、倒影、逆行、扩大 / 缩小、裂解、节奏移位），按 AABA、ABAC 等句式组织。
5. **试听与导出**：和弦铺底 + 旋律合成，用统一的播放控制条播放；导出 MIDI、Synthesizer V 或 OpenUtau 工程。

数据模型直接用 `score.Analysis`（`Melody.Notes`、`Chords`、`Beats`、`Downbeats`、`Key`）。这样可以复用乐谱页已有的乐谱排版（`MelodyLayout`、`Measures`）、和弦记号（`Symbol(..., "jazz")`）、多轨卷帘、和声色彩（`ColorAnalysis`）、合成（`ChordPad`、`MelodyPiano`、`TrackPCM`）、导出（`MIDI`、`SVPExport`、`USTX`）和 `transport` 播放控制条，灵感页基本只需要写「生成」这一侧。

## 2. 哼唱转乐句

| 环节 | 做法 | 依据或可复用的部分 |
|---|---|---|
| 音高曲线 | 录音时直接用 `score.KaraokeSession` 实时取得 F0、清晰度和响度帧，与 K 歌同一套 | `internal/score/karaoke.go` |
| 音符切分 | 对 F0 帧做「音高状态 + 起音 / 持续 / 静音」的 HMM，Viterbi 求音符序列；清晰度低的帧算静音 | pYIN 与 Tony 的音符 HMM（Mauch & Dixon 2014；Mauch et al. 2015, *Computer-aided melody note transcription using the Tony software*） |
| 速度与量化 | 默认按节拍器速度量化；不用节拍器时，从起音间隔的直方图估计速度，再按 1/8 或 1/16 网格量化，允许三连音 | 用户确认的速度优先，估计值只作建议 |
| 转音与连音 | 响度包络在新音节处会先下凹再起音（辅音、换气）。音高变化处没有这种起音时，判为同一音节内的转音，归为一组连音 | 与乐谱页歌词分组「一个字唱多个音」相同的表示，乐谱和 MIDI 现成可用 |
| 拟声词歌词 | 每个音节一个拟声字。长音用「啊」，短促的音用「哒」，句尾用「嗯」。也可以在界面上切换一组（例如「啦 / 噜」偏明亮，「呜 / 哦」偏抒情） | 歌声合成工程需要每个音都有歌词，拟声字保证 SV / OpenUtau 导出能唱 |
| 调性 | 对量化后的音符做 Krumhansl 调性剖面匹配，再结合首尾音和长音 | 分析引擎已有调性剖面（`KeyProfiles`），可移到 Go 端对少量音符直接计算 |

风险：哼唱跑调和节奏松散会影响结果。所以量化后的乐句要能在卷帘里拖动修改，并且可以「按建议的调吸附音高」。

## 3. 和声配置

### 3.1 理论框架（规则层，确定性）

- **功能和声与和弦—音阶理论**：根据强拍旋律音和长音筛选候选和弦：和弦音最好，张力音（9、11、13）可以接受，避免音（avoid note，例如大调 IV 级以外和弦上的 11 音）扣分。参考 Mark Levine, *The Jazz Theory Book*（1995）；Berklee 的重配和声体系。
- **候选和弦词表**：自然音三和弦和七和弦；副属和弦（V/x）；ii–V 链；三全音替代（subV）；调式交替（借自同主音小调，例如 bVI、bVII、iv）；减七经过和弦；挂留与加音和弦；爵士的 Δ7 / -7 / ø / 7alt 记号。
- **进行语法**：按 Rohrmeier（2011/2020）的调性和声生成语法，以及 Steedman（1984）的爵士和弦语法，给常见进行打分：T–S–D–T、ii–V–I、副属链、终止式。
- **求解**：每拍或每半小节一个时间片，在候选和弦上做 Viterbi / beam search。得分 = 旋律—和弦匹配 + 进行转移 + 和声节奏（强拍换和弦）+ 风格权重。思路与 Simon et al., *MySong*（CHI 2008，为演唱的旋律自动配伴奏的 HMM）相同，只是把训练出的转移矩阵换成按风格的规则权重。
- **风格预设**：同一求解器换权重，就得到不同风格：
  - 流行：自然音为主，四和弦循环。
  - 爵士：七和弦，ii–V 和三全音替代权重高，和声节奏更密。
  - 重配和声：鼓励副属和弦和调式交替。
  - 调式：保持 Dorian / Mixolydian 等调式色彩，避免属到主的解决。

规则层总能给出结果，可离线使用，结果可以解释（每个和弦为什么被选中）。产出 N 套候选，每套附匹配度和「和声色彩」曲线（复用 `ColorAnalysis`，见 [harmony-color.md](harmony-color.md)）。

## 4. 动机发展

- **确定性变换（Go 端实现）**：
  - 原样重复与模进：按调内或半音移位。
  - 倒影：以首音为轴翻转。
  - 逆行。
  - 扩大与缩小：时值 ×2 或 ÷2。
  - 裂解：取动机头或尾反复。
  - 节奏移位：错半拍。
  - 句尾改写：落到不同的终止音。
- **句式模板**：AA'BA、ABAC、问答句（前句停在半终止，后句停在全终止）。
- **组合方式**：用户选句式，系统把各段的变换列成候选。和声随句式重新求解：例如 A' 段换成三全音替代或调式交替，B 段转到关系调或下属方向。
- 由变换生成音符，保证结果和动机有可辨认的联系；候选按「与动机的相似度」和「与和声的匹配度」排序。

参考：Schoenberg, *Fundamentals of Musical Composition*（动机、乐句与乐段的发展手法）。生成式模型方向（Coconet、Music Transformer 等）需要训练或部署模型，不作为第一阶段方案。

```
灵感
├─ 动机    [录音设备 ▾] [速度 ♩=90] [拍号 4/4] [预备拍 1 小节]  ● 录音 / 重录
│          量化后的卷帘（可拖动）+ 五线谱预览（连音、拟声字）

├─ 发展    句式 [AA'BA ▾]  每段的变换（可改）→ 生成乐段
└─ 底部    统一播放控制条（transport）；导出 MIDI / SV / OpenUtau
```

## 7. 分阶段

| 阶段 | 内容 | 验证 |
|---|---|---|
| M1 | 灵感页骨架；录音 → 音符切分、量化、连音、拟声字；卷帘编辑；播放与 MIDI 导出 | 用合成的 F0 序列和真实哼唱样本，回归测试切分结果（音高、起止、连音分组） |
| M2 | 规则和声求解器与风格预设、候选评分；和声色彩曲线 | 经典旋律（公有领域民歌、爵士标准曲的旋律片段）配和声，与原和声比较匹配度 |
| M3 | 动机变换与句式生成，和声随句式重解 | 每种变换的单元测试；句式生成的听感检查 |
