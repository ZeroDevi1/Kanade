# Windows 测试清单

macOS 只做冒烟测试（引擎能启动、界面链路通、错误提示正确）；推理与训练的实测在 Windows + NVIDIA GPU 上进行。
本清单列出 macOS 上**没有覆盖**、需要在 Windows 验证的项目，按依赖顺序排列。

构建：执行 `go tool mygo build -platform windows/amd64`，产物为 `build/windows-amd64/Kanade.exe`。
（Windows 上直接构建也会产出 NSIS 安装包 `Kanade Setup <版本> amd64.exe`，目前只验证裸 exe。）

2026-10-20 在 Windows 11 + RTX 5060（8 GB，Blackwell）上完成了一轮实测，结果标在各项后面；
分轨模型的评估见 [stems-evaluation.md](stems-evaluation.md)。

## 15. 2026-10-25：RVC 训练提速（RTX 5060 经 Oculink 外接）

Oculink 一般是 PCIe 4.0 ×4（约 7.9 GB/s，台式机 ×16 插槽的四分之一）。训练本身主要吃显卡算力，带宽影响集中在
每步把批数据拷到显卡，以及显存不够时驱动回退到共享内存（经 ×4 链路读写系统内存，速度会降到几分之一）。改动：

- 每次训练由新启动的 worker 运行（engine.json 的 fresh_tasks），worker 不再调用 torch.cuda（显存经 nvidia-smi 查询）：
  之前推理加载的模型与 CUDA 上下文不再与训练争用显存。dev-mock 端到端测试覆盖 worker 的更换。
- 数据缓存到显存改为默认「自动」：数据量不超过显存的 10%（8 GB 约 12 分钟 48 kHz 切片）时缓存，免去每步经 PCIe 的拷贝
  与 Windows 上 DataLoader 工作进程的开销；专业模式可强制开 / 关。
- 训练精度由 Kanade 写入本次训练专用的 Applio 设置（默认 fp16，可选 bf16 / fp32），不再读用户另装的 Applio 的设置。
- 训练中每 15 秒查询显卡，进度里显示 PCIe 链路、显存与每轮耗时；显存将满（余量 < 300 MB）或负载下链路低于 3.0 / ×4 时提示。
  训练结束后 kanade-train.json 记下每轮耗时中位数、PCIe 链路、显存峰值、精度与是否缓存。
- [x] macOS（假 nvidia-smi）：查询解析、缓存估计（10 分钟 48 kHz ≈ 625 MB，8 GB 卡自动缓存）、显存将满与链路降级的提示。
- [ ] 训练时进度显示「PCIe 4.0 ×4」；若是 1.0 / 2.0 或 ×1 / ×2，检查 Oculink 线缆、BIOS 中该 M.2 / PCIe 口的代数设置，
  以及 Windows 电源计划中的「PCI Express → 链接状态电源管理」（设为关闭）。
- [ ] 同一数据集各训 10 轮比较「每轮 N 秒」：缓存 开 / 关，fp16 / bf16；先推理一段再训练，确认显存峰值不再包含推理模型。
- [ ] 显存将满的提示出现时：NVIDIA 控制面板 → 管理 3D 设置 → 「CUDA - 系统内存回退策略」设为「首选无系统内存回退」，
  超出显存时会直接报错而不是悄悄变慢，便于判断该降 batch 还是关缓存。
